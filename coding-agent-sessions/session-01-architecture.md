# Session 01 · 产品架构设计

## 轮次 1：需求理解与方案设计

### Prompt（关键部分）
```
阅读我项目中的核心文件：Game.js / index.js / Sudoku.js以及作业要求文档和上次作业的EVOLUTION文档，
基于"AI 不只是一个功能，而是一个可对话的伙伴"的想法，请提出 3 种不同的 AI 能力设计方案。
每种方案需要包含：AI 角色、核心交互、技术实现初想。
最后，从软件工程的角度，推荐一个最易演进且体验最好的方案，并说明理由。
我们先不写代码，只做设计决策。
```

### Agent 回复摘要
- 阅读了 Sudoku.js（棋盘逻辑、候选数计算、提示系统）、Game.js（历史栈、探索模式、死胡同记忆）、grid.js（Store 桥接层）
- 提出了 3 种 AI 方案：
  1. **AI 导师**：纯本地规则引擎 + Mock LLM 模板，策略检测 + 中文解释
  2. **AI 对弈伙伴**：观察者模式 + 主动发言 + 人格化对话
  3. **AI 复盘教练**：赛后路径分析 + 最优解 diff
- 推荐方案一（AI 导师），理由：架构解耦最清晰、可演进为方案二/三、确定性核心 + 概率性外衣、对 AD 最友好

### 决策点
- **用户确认**：选择方案一（AI 导师），要求策略引擎纯本地 + LLM 翻译层使用 Mock 模式

## 轮次 2：驾驭文件生成

### Prompt（关键部分）
```
在开始写代码之前，我需要先建立项目的驾驭文件。请帮我生成以下两个文件。
项目架构约束（必须遵守）：
- 已有代码：Sudoku.js、Game.js、index.js，这些文件的公共接口不可修改
- 策略引擎是纯本地规则引擎，LLM 翻译层使用 Mock 模式
文件 1：AGENTS.md（角色定义、核心原则、工作流规范、代码规范、禁止行为清单）
文件 2：PLAN.md（WU 拆分，每个 ≤ 100 行，含目标、涉及文件、验收标准）
```

### Agent 回复摘要
- 生成了 AGENTS.md：定义 Agent 角色、6 条核心原则、计划→实现→验证 三步工作流、WU≤100 行的代码规范、8 条禁止行为
- 生成了 PLAN.md：11 个 WU 分三阶段，WU-02~05（四个策略）可并行，预估 675 行新增代码

### 决策点
- **用户确认**：AGENTS.md 和 PLAN.md 通过，开始执行 WU-01
